# 封面气泡拖动与自动避让设计说明

> 对应 2026-10-07 迭代：封面编辑增加气泡拖动、冲突检测、候选布局建议、拒绝/撤销、导出校验与旧作品兼容。

## 1. 需求摘要

- 气泡可拖动（含键盘微调），靠近封面标题或装饰波形时实时提示冲突，并给出可采用的位置。
- 切换方形/竖版后仍可继续调整；位置不能因重新打开作品或改变预览大小而漂移。
- 不能给所有作品写死位置：每次都基于当前标题、气泡文字、比例计算，并至少比较两种候选布局。
- 用户可以拒绝建议、撤销操作；确实无法容纳时说明原因，且不保存越界/重叠的封面。
- 旧作品没有布局信息时保持原图，进入编辑后由用户明确决定是否启用新排版。

## 2. 坐标系与持久化（解决“预览大小变化漂移”）

- 所有碰撞计算在**设计像素**坐标系中完成：方形 900×900，竖版 900×1200，宽度恒为 900。
- 存入 `CoverConfig.layout` 的全部是**百分比与相对字号**：

```ts
interface BubbleLayout {
  version: 1;
  x: number;        // 气泡中心 x，占宽度 0..100
  y: number;        // 气泡中心 y，占高度 0..100
  fontPct: number;  // 字号占宽度百分比，42px/900 = 4.667
  widthPct: number; // 气泡排版宽度占宽度百分比
  strategy: 'manual' | 'move' | 'wrap' | 'scale';
}
```

- 预览宽度变化时，`px = pct/100 * 预览宽度`，映射关系不变；导出仍在 900 宽设计坐标绘制。因此“编辑时位置 = 预览位置 = 导出位置 = 重开位置”。
- 行数不入库：渲染器与求解器用同一份纯函数 `wrapText()` 按当前字号/宽度重新换行，避免文字编辑后数据过期。

## 3. 碰撞范围如何计算

核心层为纯 TypeScript（`src/core/cover-layout.ts`），不依赖 Canvas/DOM，便于单测。

### 3.1 文字度量

无浏览器环境，按字符估算 em 宽度：

- 中日韩文字与全角标点：`1.0em`
- 拉丁/数字：`0.56em`
- 空格：`0.32em`

实测渲染器使用的 `sans-serif` 在 42/92px 字号下该估计偏保守（略宽于真实值），宁可多留空隙。

### 3.2 障碍物（碰撞盒外扩统一间隙 `CLEAR_GAP = 28px`）

1. **标题盒**：按 92px 字号测量；单行宽度超过 720px 时先缩到不小于 74px（0.8 倍），仍超则贪心换行为最多两行。末行基线固定在 `0.30H`，包围盒按字号上升量/下降量估算，再向四周外扩 28px。
2. **装饰波形带**：正弦曲线中心 `0.43H`、振幅 62px、描边半宽 7px，视为**贯穿整幅宽度**的条带，上下再外扩 28px。
   - 方形下，标题盒外扩后与波带外扩后相接，合并为一个障碍区；
   - 竖版下二者之间留有窄缝，求解器仍可比较“夹缝”和“下方”两个位置。
3. **安全边距**：气泡包围盒必须完全位于 `36px` 内框中，越界记为 `bounds` 冲突。

气泡盒 = 多行文字块 + 内边距（x 22 / y 14），行高 1.32 倍。碰撞用 AABB 相交判定。

### 3.3 为什么不能只算“当前画到的墨迹”

波形是一条上下摆动的线、标题文字外形也不规则；若按墨迹精确判定，气泡贴近笔画间隙时会被误判为安全，视觉上仍压迫。统一外扩 28px 是“可读净空”，保证提示与实际观感一致。

## 4. 移动 / 换行 / 缩放的采用顺序

最小移动距离**不**作为首要目标（近但压字没有意义），缩字号也不优先（直接损害可读性）。策略按可读性损失排序，同策略内才取位移最小：

1. **移动 `move`**：保持 42px、单行，在安全区候选网格（水平 居中/两侧/四分位，纵向每 28px 一格）中选离当前中心最近的一格。
2. **换行 `wrap`**：保持 42px，按 80% 画面宽度贪心换行；行数越少越好，同等行数取位移最小。
3. **缩放 `scale`**：字号按 38→34→30→28 逐档尝试，单行放不下时允许在该字号下换行，取能放下的最大字号。

求解器对三种策略都计算**所有可行候选**并返回，UI 标注“推荐”（按上述顺序第一个可行者），用户可改选其他候选、拒绝建议或手动拖动。所有候选在返回前都会再次过碰撞判定，保证“给出的位置一定可采用”。

不可行判定：连 28px + 换行都无法进入任何安全格时，返回原因（最小需要高度、当前比例可用高度、建议删减文字或切换方形），界面阻止保存，渲染器同样拒绝导出。

## 5. 三个对照案例（选择依据，非固定位置）

### 案例 A：长气泡

气泡文字 22 个汉字，用户拖到标题附近。

- 单行 42px 所需宽度 ≈ 880px，超过可用内宽 828px → **移动策略不可行**。
- 换行：按 80% 宽排成 2 行，气泡变高，移动到波带下方，字号不变 → **推荐**。
- 缩放：38px 单行宽 ≈ 796px 可放下，同样要移到波带下方，但字号缩小约 10% → 列为备选。
- 依据：换行保留原字号，可读性损失小于缩字；二者位移相近，不按“距离小”取缩放。

### 案例 B：窄画面（竖版 3:4）

短气泡（4 字）拖到画面正中（y≈50%）。

- 竖版波带约在 35%–51% 高度，气泡与波带冲突。
- 移动：单行 42px 只需下移约 8% 画面高度即可离开波带 → **推荐，位移最小**。
- 换行：两行气泡更高，需要更大下移，且平白增加一行 → 备选但排序靠后。
- 说明：同一百分比布局切到竖版后直接复用；若产生新冲突，建议面板按竖版障碍重新计算，可继续调整。

### 案例 C：标题较大

封面标题 12 个汉字：92px 放不下 → 缩到 74px 仍超宽 → 排成两行，标题盒明显变宽变高，并与波带外扩区合并。

- 小气泡拖到左上角：短标题时标题两侧存在可放置的边角格；大标题把边角格全部覆盖 → 边角候选消失。
- 波带贯穿全宽，水平移动无法离开障碍 → 最近可行格只剩障碍区下方，位移明显变大；候选的位移差被如实展示。
- 换行/缩放不能解决“障碍横向贯穿”的问题（换行只会让气泡更高），仍以移动为准；没有任何安全格时才进入缩字档。
- 依据：障碍范围随标题实际排版变化，候选位置是算出来的，不是预设坐标。

## 6. 交互流程

1. 拖动中：气泡跟随指针（限制在画面内），冲突时气泡描边变红并标注“与标题重叠 / 与装饰波形重叠 / 超出安全边距”，障碍盒显示红色虚线外框。
2. 松手后：若有冲突且存在候选，弹出建议卡，按 移动/换行/缩放 列出候选及代价（位移百分比、行数、字号变化），推荐项置顶标注。
3. 用户可：点选任一候选；关闭卡片（拒绝建议，冲突徽标保留、保存仍阻止）；手动拖到安全区；撤销（Ctrl+Z 或按钮，恢复到拖动/采纳前布局，含从旧排版“开始调整”后的回退）。
4. 保存前 `useStudio` 调用 `validateCoverConfig()`；不通过则给出中文原因、不调用渲染器、不写 IndexedDB。渲染器内部再做一次防御性校验，越界布局直接抛错，保证任何路径都导不出越界图。
5. 无候选时展示求解器返回的具体原因（文字过长/可用高度不足），保存按钮禁用。

## 7. 旧作品兼容

- `layout` 字段缺失即视为旧作品：渲染器走原始绘制路径（单行文字、原样位置），作品集与导出保持原图，不做任何自动迁移。
- 旧作品进入封面编辑时显示横幅：“当前为旧版原始排版，未启用碰撞检测”，提供【开始调整】（在当前 `bubbleX/bubbleY` 位置生成布局，纳入检测与撤销栈，未保存前可撤销回原图）与【保持原图】。
- 新建作品由预设直接携带合法 `layout`（默认位置已通过双比例可行性校验）。

## 8. 测试策略

- `core/cover-layout.test.ts`：三个对照案例的候选与排序、标题-波带合并、越界、文字超长不可行与原因、百分比坐标缩放不变性、旧配置免校验。
- 渲染器测试：新布局按行绘制、旧配置走原路径、越界布局拒绝导出。
- 工作流测试：冲突布局阻止保存且不调用渲染器；旧作品可正常保存。
- 组件测试：旧作品横幅、冲突时出现至少两个候选、拒绝/采纳/撤销、切竖版后重新建议。
